How to recognize whether legacy notes were authored by a human or generated by an AI when Git author data is missing, and how to record provenance accurately.

## Goal & Motivation
I want to preserve context in my [[Obsidian vault|vault]] on what was [[human vs ai text context|written by a human or AI]].

AI still makes errors, so human thoughts, direct experience, and questions carry higher signal. The human prompt often holds more value than the raw generated output because it captures intent.

## Context & Legacy Notes
Most [[note taking|notes]] used to be hand-authored. Now tools like [[Claude Code]] and [[antigravity]] are used for [[agentic note taking]].

Older notes often contain AI answers that show up as manual commits because they were pasted in or committed without bot author metadata. Differentiating legacy notes allows Git commit metadata to reflect true authorship.

Updating historical Git commits via force push is viable as a one-off migration, provided downstream consumers like the [[2026-08-18 pkm voice agent addon install|telegram bot]] reset cleanly.

## Detection Heuristics
- **Structural markers:** Typical LLM patterns like symmetric bullet lists ending in bold colons, long numbered explanations, and generic transition phrases.
- **Prompt vs response anchors:** Quotation blocks (`> prompt`) followed by structured multi-paragraph responses.
- **Legacy tags:** Outdated tags like `#ai-generated`, `#ai-assisted`, or `tags: [ai, claude]` in frontmatter.
- **Temporal calibration:** Comparing note creation dates against model release windows and subscription logs (e.g. Copilot/GPT-4 in early 2024 vs. Claude 3.5 Sonnet mid-2024 vs. Gemini in 2026).
- **Vault logs:** Matching daily notes where tool trials were logged (e.g. [[2026-01-19 try CLI LLMs]], [[2026-08-15 claude 1 million research]]).

## One-Off Git History Migration Strategy
A Python script using `git log -p` and `git-filter-repo` can scan past commits and rewrite history:
1. Scan historical commits and identify generated blocks.
2. Split mixed commits into a human commit (prompt and notes) followed by an AI commit (generated response).
3. Preserve submodule pointers so child repositories remain untouched.
4. Downstream servers (like the Telegram bot) perform a single `git reset --hard origin/main` after the rewrite.

## Model Distinction in Git Authorship
Direct agent edits should use the model identity as the primary [[git author]]:
```bash
git commit -m "add: note" --author="claude-3-7-sonnet <claude@anthropic.com>"
```

For human commits incorporating AI drafts or assistance, keep the human author and append standard Git trailers:
```git
Co-authored-by: claude-3-7-sonnet <claude@anthropic.com>
```

Using native Git author metadata eliminates the need for `#ai-generated` [[tag|tags]], keeping notes shorter and adhering to [[minimal notetaking]]. Author rules are documented in [[AGENTS]].

## Prompt Tracking & Feedback
Using [[agent answers in callout]] works for inline answers, but callouts reduce readability and editability for long text blocks.

When prompting via CLI or [[agentic note taking on mobile|on my phone]], having the AI generate clean note markdown directly is preferable. Recording the prompt in the commit message or an external log keeps prompt history without cluttering the note body.
