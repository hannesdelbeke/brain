a checklist question like "does X help?" only has room for one answer: yes or no. plenty of real answers are actually "yes, but only when Y is true" — and a checklist has no place to write that down.

**example:** you want to know if bold text helps someone remember a fact. you test it with easy, obvious facts anyone could skim and get right anyway. nobody needed help remembering, because the test was too easy for anything to matter. you write down "bold: no effect."

later, someone tests the same question with hard, easy-to-confuse facts buried deep in a long document. now bold jumps out and genuinely helps. same question, harder test, opposite answer.

the checklist can't hold both results — it only has one row for "bold." so whichever test happened to run first gets written down as *the* answer, and "bold didn't help on this one easy test" quietly turns into "bold never helps."

**the fix:** before trusting a yes/no answer to "does X help," ask what the test actually looked like. a test that finds nothing usually just means the test was too easy to find anything with — not that X does nothing. the honest version of "does X help" is almost always "help with what, under which conditions" — two questions squeezed into what looked like one.

**where this shows up:** medicine dosage charts, app a/b tests, "best practice" lists, nutrition advice — anywhere someone turned "it depends" into a tidy table, because a table looks more finished than a paragraph that admits it depends.
