Many of my projects have their own README files, formatted to show on [[GitHub]].
And I create mirror pages in Obsidian.

It'd be cool if creating a mirror page was optional, and I could see, and edit, all my READMEs in Obsidian. - [[use more links in life]]

Idea 1: 
Clone all repos under a repo folder in Obsidian, now I can link to all READMEs.
Git cloning would require me to have all projects cloned, or some links might break.
Bonus: I now can also link to code files in my projects.
CON
- Need to figure out how to exclude projects from Obsidian's git management, it would clash with my WIP git states during development

Idea 2: (picked, see Plan below)
A script that only downloads all READMEs, instead of cloning all projects.
It could run on startup, or trigger manually.
CON: 
- How to handle editing README in Obsidian, and uploading back to git?
	- consider read-only?

## Plan

Idea 2, read-only, as a local copy: a script copies every repo README into a gitignored `projects/` folder in the vault, renamed to the repo name. Read them and link them like any note; edit them in the repo.

Facts this is built on:
- `%USERPROFILE%\Documents\GitHub` holds 28 repos, 26 with a README, and the vault is one of them (sibling, not parent).
- This vault's git remote is public. Many sibling repos are private repositories.
- The [[Obsidian plugin - Git]] auto-backup commits everything that is not ignored (`auto backup: <date>` commits).
- The vault is flat, one folder deep only for `image/` and `skills/`.

Trade-off accepted: `projects/` is gitignored, so the mirror only exists on this machine. On another machine or on mobile the `[[<repo> README]]` links resolve to nothing until the script runs there. That is the price of not pushing private work READMEs into a public repo, and READMEs are dev-machine context anyway.

Why the others lose:
- Idea 1, cloning repos into the vault: puts private code inside a public vault repo where a plugin runs `git add -A` on a timer. Also 26 files all named `README.md`, the clash described in [[submodule wikilink clashes]], and Obsidian indexing 28 working trees.
- Junction or symlink per repo with the target gitignored ([[mklink windows - soft & hard link]]): same `README.md` name clash, same private-content-in-a-public-repo exposure if the ignore line is ever dropped, and Obsidian walks the whole working tree.
- Hard link per README, renamed on the vault side: this is the only option that gives real two-way editing, but a `git checkout` in the repo replaces the file and silently breaks the link, so the vault copy goes stale without a signal.
- Separate vault plus `obsidian://` URI: covered in [[TODO include project wikis in Obsidian]], it needs a `.obsidian` folder in every repo and the links break outside Obsidian.
- Do nothing: the hand-written mirror notes (`datafix.md`, `figmapy.md`) stay the only entry point and keep drifting from the repo.

Steps:
1. Add to the vault `.gitignore` ([[gitignore]]):
   ```
   # generated mirror of project READMEs, may contain private work repos
   projects/
   ```
   Do this before step 3 so the auto-backup never sees the folder.
2. Layout: `projects/<repo name> README.md`, e.g. `projects/FigmaPy README.md`, linked as `[[FigmaPy README]]`. The repo name suffix avoids both the 26-way `README.md` clash and the existing hand-written notes `datafix.md` and `figmapy.md`, which can now link to their mirror.
3. Write `skills/mirror_readmes.py`, stdlib only:
   ```python
   from pathlib import Path

   ROOTS = [Path.home() / "Documents" / "GitHub"]
   VAULT = Path(__file__).parent.parent
   OUT = VAULT / "projects"

   OUT.mkdir(exist_ok=True)
   written = set()
   for root in ROOTS:
       for readme in sorted(root.glob("*/README.md")):
           repo = readme.parent
           if repo == VAULT or not (repo / ".git").exists():
               continue
           header = (
               "---\ntags:\n- readme-mirror\n---\n\n"
               f"> [!info] Read-only copy, regenerated by `skills/mirror_readmes.py`.\n"
               f"> Source: [{readme}]({readme.as_uri()})\n\n"
           )
           out = OUT / f"{repo.name} README.md"
           out.write_text(header + readme.read_text(encoding="utf-8"), encoding="utf-8")
           written.add(out.name)

   for stale in OUT.glob("* README.md"):  # repo renamed or gone
       if stale.name not in written:
           stale.unlink()
   ```
4. Run `python skills/mirror_readmes.py` from the vault root when a README changed. Manual for now; a Task Scheduler entry or a call from the same place the indexer runs can come later if manual runs get annoying.
5. Edits do not flow back. The callout at the top of each mirror carries a `file://` link to the real README, so editing means opening that file, and the commit happens in the repo where it belongs. If two-way editing turns out to matter more than the stale-link risk, revisit the hard link option above.

Not needed for this: Obsidian's "detect all file extensions" setting, which only matters for the clone or junction options where you also want to open `.py` files.
